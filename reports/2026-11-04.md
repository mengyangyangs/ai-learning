# 每日 AI 资讯报告 · 2026-11-04

**日期：** 2026 年 11 月 4 日（星期三）
**今日主题一句话概括：** 11 月 3 日这一天，AI 行业的主线从“更大、更快”转到了“能不能验证”：Anthropic 要给模型输出开密码学收据，OpenAI 要证明模型能做出真能造出来的硬件，而两张新的 Agent 成绩单则在追问——代码 Agent 到底会不会干活、测得到底准不准。

> 说明：本报告基于 2026 年 11 月 4 日通过浏览器阅读的公开报道与一手页面整理，包括 TechCrunch 的 FlashProve 全文、Anthropic 与 Momentic 的官方博文、AMD 官方财报新闻室、Apple 开发者公告的多源交叉，以及 DeepSeek、Apple 中国、Kimi、WIRED 调查、NorthCUA、Perplexity 的多源整理。凡是厂商自报的基准、价格与订阅数字，均已标注来源性质；凡是“据报道”“二手整理”的内容，均已注明；未官宣的模型线索与估值传闻单独说明，不与已发布事实混写。Kimi K3.1 Pro 权重发布承诺的到期日就是今天，截至本报告撰写时，仍以 Moonshot 官方页面为准，不提前断言已经发布。

## 一、核心要点

### 1. FlashProve：Anthropic 想给“这是哪个模型答的”开一张密码学收据

11 月 3 日，Anthropic 发布了一个开源研究原型 FlashProve，解决的问题比听起来更实际：今天你调用一个 API，对方说“这是某某模型在回答”，你其实无法验证——服务商可能悄悄换成更便宜的模型省成本，也可能换成更强的模型刷榜。

- **做法分两步：** 实验室先为一套模型权重发布一个很短的“指纹”（密码学承诺），权重本身不公开；模型回答问题时，再附上一份证明文件，证明“这份回答确实出自那套已承诺的权重”。持有承诺、提示词和回答的任何人，都可以在本地设备上验证，不需要看到权重。
- **用到的技术：** 一类零知识证明（zkSNARK），属于与以太坊 ZK Rollup 同源的基于哈希的证明体系；代码与技术规范以 Apache 2.0 开源，形式化证明用 Lean 写成。
- **实测数字（原型口径，不是产品承诺）：** 在 Meta 的 Llama 4 Maverick（400B 参数的 MoE 模型，约 17B 参数参与每个 token）上测试，证明约 19MB（对应 1024 个 token 的请求），在 24 核 CPU 上验证约 17 秒，单张 H100 上证明速度约 110 token/s，但证明的 GPU 时间约为正常推理的 70–95 倍，单个请求要等约 5 分钟。
- **边界要说清楚：** 目前只覆盖贪心解码、整数运算模型、1024 token 以内的上下文，且假设 MoE 架构；它证明的是“哪个模型算的”，不是“答案对不对”；形式化工作也不覆盖全部实现边界（论文注明：快速执行代码与 Lean 实现的一致性未被形式化保证，哈希函数的安全性依赖理想化假设）。Anthropic 明确表示：这只是中期进展分享，目前没有在任何实验室部署的计划。

**一句话判断：** 这不是一个马上能用的产品，而是一块“可验证 AI”的基础设施拼图——它的真正价值在于让“模型身份”从口头承诺变成可审计的证据。以后看到“某服务偷偷降级模型”的质疑时，可以问一句：它敢不敢附上证明？

### 2. OpenAI 的硬件实验：模型一周画出设备，但“能造出来”是另一回事

同一天，OpenAI 公布了“为物理世界加速工程”的进展，核心是一次刻意设计的实验：两名员工以副业形式，用 GPT-6 Astra 在不到一周内设计出一台“用语音与 Codex 对话”的设备——从外壳、内部结构件、元器件选型、PCB 布局布线，到固件、用户界面和与 Codex 的集成，全部由模型主导，团队不直接改设计输出。随后代工厂在不到一个月内生产出一小批样机。

- **诚实的部分比 headline 更值得读：** OpenAI 自己承认，从“屏幕上的设计”到“工厂能组装”，中间经过了好几轮审校——Astra 没有始终考虑到制造约束、公差和装配细节。这正是工程 AI 目前的真实分界线：画得出，不等于造得出。
- **配套的基准数字：** 在 BenchCAD 2.0 上，一个未具名的新内部模型平均分为 0.875，GPT-6 Astra 在最高推理档位为 0.594。BenchCAD 2.0 考的是从工程图或渲染图重建三维零件与装配、从电路板图像恢复连接，评分看的是几何、零件位置与电路连通性，**不评估可制造性与物理性能**。
- **不要把两个 BenchCAD 数字混在一起：** Astra 发布时宣传的 95.9% 是旧版 BenchCAD 的体素重叠度（voxel IoU），与 BenchCAD 2.0 的 0.875 / 0.594 不是同一版本、同一口径，不能直接对比出“进步了多少”。
- **同一批进展还包括：** OpenAI 硬件团队的 token 用量自 2 月以来增长了 23 倍；与 Chip Ganassi Racing 扩大合作，把三维扫描的现成零件转成可编辑 CAD 模型与二维制造图纸；与 Mazda 的空气动力学与碰撞安全工程师启动新的车辆设计研究合作。

**对普通人的意义：** 硬件设计的瓶颈正在从“画图”移向“验证与制造”——以后这类新闻要看的不是“几天画完”，而是“第几版才通过工厂评审”。

### 3. 两张 Agent 成绩单：会写代码的 Agent，不等于会测产品的 Agent

#### Momentic QA Bench：专业 QA Agent 找到了 19.3% 的 bug，通用编码 Agent 只有约 6%

Momentic 公布了 QA Bench：把 Agent 放在 4 个真实开源 Web 应用（Gitea、Metabase、Twenty、Saleor，合计 19 万+ GitHub star）里跑 20 个产品区域，在 30 或 60 分钟内找 bug，对照 1396 个人工标注的 bug 评分。

- **结果（60 分钟，厂商自建自评，须打折看）：** Momentic 自家的 Mo 平均找到 269.3 个（召回 19.3%、精确率 84.2%、每个确认 bug 成本 2.67 美元）；最好的通用编码 Agent 配置是 Codex + GPT-6.1 Sol + Playwright MCP，找到 86.3 个（6.2%、86.0%、0.80 美元）；Claude Code + Opus 5.5 + Playwright MCP 找到 59.0 个（4.2%、4.09 美元）；Devin 27 个（1.9%）。
- **三个细节比名次更重要：**
  - **工具和模型一样重要：** 同一模型换浏览器集成，结果能差 10%–58%——Playwright MCP 普遍优于 agent-browser。选 Agent 时只比模型，等于只比了一半。
  - **时间花得值不值：** Mo 从 30 分钟到 60 分钟多找到 52% 的 bug，单位成本只涨 5%；而 Codex 的 Terra 配置在 60 分钟反而比 30 分钟找到的更少——通用编码 Agent 似乎“逛一圈就收手了”。
  - **天花板仍然很低：** 即使是最好的 Mo，也还有约 81% 的标注 bug 没找到；Metabase 最难，Mo 只找到 9%，Codex 只有 3% 左右。所谓“AI 替你测完”，目前离现实还很远。
- **局限必须同时写上：** 这是 Momentic 自建、自跑、自评的基准（裁判是 GPT-6.1 Sol，标注 bug 的候选也来自各家 Agent 的探索），Devin 只有单次运行，且 Codex 的部分运行开了联网搜索。数字可用于“相对排序参考”，不能当作采购依据。

#### NorthCUA 与 CUA-Master：开源电脑 Agent 正在追上闭源大模型

11 月 3 日，基于 Qwen3.5 的开源电脑操作 Agent 家族 NorthCUA 发布：Nano 9B、Mini 35B、Pro 397B（每 token 激活 17B），Apache-2.0 开源，配官方 Harness 使用。厂商报告：Pro 在 OSWorld-Verified（361 个桌面任务）上成功率 88.64%，在 WebArena-Verified（812 个网页任务）上 73.89%，均高于其报告中对比的 Qwen3.8-Max 与 Kimi-K3；还有一个 Ultrafast 变体，在匹配成功的 WebArena 任务上平均快 2.3 倍。同日，CUHK、清华与 JD 的 CUA-Master-27B 也报告 OSWorld-Verified 80.2%。这些都是作者自测口径，尚未有独立复现，但趋势很清楚：电脑操作这个赛道，开源模型与专用 Harness 的组合正在快速缩小与闭源旗舰的差距。

### 7. 治理警示：WIRED 揭开的 400+ 深伪应用网络

WIRED 11 月 2 日的调查（基于 AI Forensics 与 Infoblox 的研究）发现：一个 400 多个应用与域名组成的网络，伪装成宠物照片编辑、语言学习、健身教练等普通工具通过了 Apple App Store 与 Google Play 的审核，却能在特定条件下（例如经 Meta 广告下载后）从远程服务器加载生成针对真人照片的性与暴力深伪内容的隐藏界面。已确认的事实是：9 月时 Google Play 上 27 款相关应用合计下载量超过 35 万（其中 DiffAI 一款超 10 万）；Apple 在 WIRED 联系后下架了 19 款（含宠物 portrait 应用 Viefur）；Apple 称这些应用过审时符合规范，之后用了“挂羊头卖狗肉”的远程替换手法，并称过去一年已因类似行为暂停了数万款应用；Apple 已在 10 月 16 日更新 App Review 指南，加强对非自愿私密影像与评审期隐瞒功能的限制。研究者追踪到的线索指向中文代码库、中国托管服务与一家香港注册实体 KeLing Technology Limited，Meta 称此前已于 2025 年封禁该实体。**给普通用户的提醒：** 审核通过不等于终身安全——凡是要求上传真人照片、又在广告里暗示“换脸/脱衣”功能的应用，都应直接避开；已经装过的，检查来源与权限，必要时删除。

## 三、给 Patrick 的实用启示 / 可以试用的点

1. **今天就去核对一件事：** 打开 Moonshot 的官方渠道，看 Kimi K3.1 Pro 的权重是否如期发布、许可是什么、文件是否完整——“承诺开源”和“真的能下载、能商用”是两回事。如果发布了，1M 上下文 + 2 美元 / 百万输入 token 的 API 是目前试长代码库、长合同任务性价比很高的选项之一。
2. **做产品的人，先看 QA Bench 再谈“Agent 替我测试”：** 即使是最好的专业 QA Agent 也还有约八成标注 bug 找不到；更现实的用法是把它当作“不知疲倦的初筛员”，再由人工复核高严重度问题，而不是直接替代发布前测试。选型时要同时比较模型与浏览器集成（Playwright MCP 在该基准上明显优于 agent-browser）。
3. **用“可验证”当筛子：** 以后遇到“某模型帮我做了某事”的宣传（无论是审代码、做设计还是出报告），多问一句证据在哪里——是像 FlashProve 那样的密码学证明，是像 BenchCAD 那样可复现的基准，还是只有一张截图。证据的等级，决定了宣传的可信度。
4. **Apple 开发者注意两个时间点：** Siri AI 的 App Intents 现在就可以在 27.3 beta 里构建与测试，但别按“12 月就能上架”排期——App Store 提交要到明年春天；中国区 Apple Intelligence 的开发者测试今天开始，做中文写作工具与视觉功能的产品可以按 Qwen 的中文表现重新测一遍，而不是直接复用海外版的评测结论。
5. **不要被 BenchCAD 的两个数字带偏：** 看到“0.875 远超 0.594”时，记得前者是未具名内部模型、后者是 Astra，且评分不含可制造性；看到“95.9%”时，记得那是旧版口径。工程能力的判断标准，永远是“第几版通过工厂评审”，不是基准分。

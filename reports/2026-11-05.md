**日期：** 2026 年 11 月 5 日（星期四）

## 一、核心要点

### 1. Kimi K3.1 Pro 权重如期落地：承诺兑现了，但“开源”有三道门槛

昨天报告里“今天最值得盯的一条”有了答案：Moonshot 于 11 月 4 日在 Hugging Face 发布了 `moonshotai/Kimi-K3.1-Pro`，兑现了 10 月 23 日“11 月 4 日前发布完整权重”的承诺。

- **规模与形态：** 2.8T 总参数、每 token 激活 104B，MoE 结构为 896 个专家、每 token 选 16 个，上下文 1,048,576 token；权重为 MXFP4、激活为 MXFP8，来自量化感知训练；另含一个 401M 参数的 MoonViT-V2 视觉编码器；共 96 个 safetensors 分片，约 1.56TB。官方推荐用 vLLM、SGLang 或 TokenSpeed 推理。注意一个工程细节：多轮工具调用时，须把完整 assistant 消息（含 `reasoning_content`）回传，否则行为可能不一致。
- **许可不是无条件 MIT：** 许可为 MIT 风格加三条：其一，以“模型即服务”方式运营、任意 12 个月内收入超过 2000 万美元的，需先与 Moonshot 另签协议；其二，月活超过 1 亿或月收入超过 2000 万美元的产品，须在界面展示“Kimi K3.1-Pro”；其三，内部使用，以及通过 Moonshot 官方产品或认证推理伙伴使用，可豁免前两条。**对绝大多数自用、微调、自部署的人，这等于免费；对想拿它转售 API 的大服务商，这是一道需要谈判的门。**
- **独立分数已经有一个：** Artificial Analysis 的 Intelligence Index 给 K3.1 Pro 55 分，比 K3 高 11 分，排在 Claude Opus 5.5（58）等少数闭源模型之后——这是第三方口径，但仍是单一指数，不是全方位复现。
- **那个“删减”要同时记住：** Moonshot 为开源版删减了进攻性安全相关训练数据，其自测显示相关任务通过率从 90.5% 降至 81%。这不是“变弱了所以安全了”：81% 的利用类任务通过率仍然意味着，任何给它 shell 权限的部署都必须先做沙箱与操作 gating。

**一句话判断：** “承诺开源”和“真的能下载、能商用”之间的最后一公里，昨天走完了——但 1.56TB 的下载量和 8 卡级数据中心硬件，决定了对个人开发者而言，API（$2/$10）仍是试它的现实路线，权重首先是给有基础设施的团队准备的。

### 2. 腾讯 Hy4 正式版：第一次“看得见、能动手”，但权重还在“未来几天”里

11 月 4 日，腾讯发布 Hy4 正式版（8 月预览版的后续），这是 Hunyuan 线第一次同时加入两项能力：视觉理解（细粒度图像处理、复杂图表分析、数学视觉推理）与电脑使用（命令行与图形界面操作，并针对 Blender、CAD 以及 Unreal、Unity、Godot 做了专项训练）。

- **能用在哪里（今天就能用）：** 腾讯云 TokenHub、WorkBuddy、CodeBuddy、元宝、ima、微信企业版智能助手 Dayuan，以及 OpenRouter、Hermes、OpenCode 等第三方 API。定价与预览版相同：约 $0.90 / 百万输入 token、$2.70 / 百万输出 token、$0.045 / 百万缓存输入 token；WorkBuddy 与 CodeBuddy 在 11 月 4–15 日免费，TokenHub 五折至 12 月 31 日。**Hy4 Flash（更便宜快速版）官方正文的说法是“即将推出”，尚无可用版本与日期。**
- **不能用的部分要说清楚：** 官方公告称“计划在未来几天发布模型权重与系统卡”——也就是说，截至今天，Hy4 正式版仍是托管服务，不是可下载的模型。预览版的权重不等于正式版的权重，预算里不要按“能自托管”去算。
- **厂商自报成绩（全部须打折看）：** WorkBuddy 评测均分 83.18、通过率 96.15%，12 个场景中 9 项居中国大陆市场第一；213 位金融专业人士、579 个真实金融任务的盲评中，Hy4 得 3.04 分，高于 DeepSeek-V4.1-Flash-1017（2.97）、Kimi K3.1 Pro（2.68）与 GLM-5.3（2.68）；内部评估的幻觉率从预览版的 12.95% 降至 7.2%（另一家二手整理引用了 15.76%→5.45% 的一组数字，口径不同，本文只采用官方公告的口径）。
- **值得单独记的一句：** 腾讯称 Hy4 借助 Hyra 2.0 研究 Agent 优化了自身预训练基础设施，使端到端吞吐提升 20.1%——这是厂商说法、无外部复现，但它与昨天 Anthropic S-1 里“AI 加速 AI 自身”的叙事是同一条线：各家都开始把“模型帮自己训练”写进发布稿，读的时候要区分“帮了多少”与“是不是已经自我改进”。

**一句话判断：** Hy4 正式版的真正增量不在榜单，而在“视觉 + 电脑操作”第一次进入腾讯的主力产品线——对做办公自动化、截图驱动流程的人，这是一个值得在免费窗口里用真实任务实测的候选；对想自托管的人，它目前还只是一个承诺。

### 3. Ripple-65B：65B 参数打 80.5 分，但“美国开源第一”这个头衔要加很多限定词

11 月 4 日，Ricursive Intelligence（由 Google AlphaChip 的创造者 Anna Goldie 与 Azalia Mirhoseini 创立，1 月获 3 亿美元 A 轮、估值 40 亿美元）发布 Ripple-65B Preview：65B 参数的稠密模型，从头训练 12T token，Apache 2.0 许可，权重已上 Hugging Face，并经 Together AI、GMI Cloud、OpenRouter 等渠道提供 API。

- ** headline 数字（厂商自报）：** Terminal-Bench 2.1 得 80.52 分，略高于 Reflection Beam 501B 的 80.1 分——差距只有约 0.4 个百分点；SWE-bench Pro v2.0 Hard 得 79.1 分（发布图口径）。公司称全部研发成本约 3200 万美元，强化学习仅用 1.4M 个 rollout，约为 Beam 的 100M+ 的约七十分之一。
- **三个限定词必须同时写上：**
  - **它不是全方位第一。** 同一张发布图里，Ripple 在 DeepSWE（44.3 vs Meta Muse Spark Open 的 60.0）、FORTRESS 对抗测试与 AutomationBench 上都落后于 Meta；Reflection 更新后的自家对比还把几个中国模型排在 Ripple 之上。所谓“第一”，限定在“美国开源模型 + 这两项基准”之内。
  - **厂商自己的材料前后不一致。** VentureBeat 指出，模型卡里 Meta 与 Inkling 的 SWE-bench Pro Hard 分数（52.3 与 2.0）与发布图（72.4 与 39.6）对不上；模型卡自己也承认 Agent 基准难以复现、换评估框架会影响分数。
  - **“65B 对 501B”是个容易误读的对比。** Beam 总参数 501B，但每 token 实际激活仅约 23B；而 Ripple 的 65B 是全部激活。**总参数决定显存与下载量，激活参数才决定单 token 的算力——拿总参数比大小，会同时夸大 Beam 的笨重与 Ripple 的轻盈。**
- **价格与上下文的两个坑：** OpenRouter 经 GMICloud 的标价确实便宜（$0.20 输入 / $0.60 输出），但该端点当前上下文上限仅 16,384 token，与宣传的约 1M 上下文不是一回事；本地部署方面，公司提到 DGX Spark 与 MacBook，但未给出统一的内存配置、速度与可用上下文，BF16 与 NVFP4 两个权重版本也要分开评估。

**一句话判断：** Ripple 值得进评估清单——Apache 2.0、无收入门槛、终端编码任务上确实能打——但不要把它当作“小模型已全面超越大模型”的证据；正确用法是拿自己的仓库与 Agent 框架实测“每完成任务成本”，而不是背诵 80.5 这个数字。

### 4. 同一天的两笔收购：OpenAI 买“存代码的地方”，Meta 买“管 Agent 的地方”

11 月 4 日，代码 Agent 的基础设施战在同一天落了两子，方向互补：

- **OpenAI 收购 Pierre Computer Company（拟收购，尚未交割）：** Pierre 的 Code Storage 将并入 Codex；已内置于 Codex 的 Trees（文件浏览）与 Diffs（变更展示）等开源项目保持开源；价格、交割日均未披露，须监管批准，交割前两家独立运营。理解这笔交易的钥匙在两天前 OpenAI 自己的工程帖：其自研单仓 Git 后端 Pando（10 周从启动到生产、4 月起承载生产流量）使中位推送延迟降低近 80%、日交付近 1PB Git 数据——Agent 并行写代码，首先压垮的是版本控制。Pando 解决的是 OpenAI 内部单仓的并行写；Code Storage 解决的是外部应用“给机器用的 Git 托管”（API 优先、quorum 一致性、32TB 级仓库、30+ 并发写）。**买下 Pierre，等于把 Codex 从“写代码的助手”向“存代码、管理代码、交付代码的平台”推了一步，直接对位 GitHub。**
- **Meta 收购 Conductor（已确认，价格未披露）：** Conductor 是让开发者并行运行多个编码 Agent（Claude Code、Codex、Cursor、OpenCode）的 Mac 应用与云服务，团队加入 Meta Superintelligence Labs。代价是现有产品迅速关停：**云服务 11 月 13 日起只读、11 月 20 日关停并开始删除云数据；11 月 4 日起停新注册与下载；本地 Mac 应用支持至 2027 年初后逐步停运；** 现有订阅者退款、Pro 功能免费保留至停运，公司称从未出售或用用户数据训练。**如果你或你的团队在用 Conductor Cloud，11 月 20 日前必须导出数据——这不是“可能关停”，是已公布的时间表。**

**一句话判断：** 两笔交易讲的是同一件事：当 Agent 一次能开几十个并行任务时，瓶颈不再是“模型会不会写”，而是“写出来的东西存在哪、谁在管、怎么合并”——OpenAI 买存储层、Meta 买编排层，下一轮竞争的战场正在从模型本身移向 Agent 的工作台。

### 5. 治理与安全：CrowdStrike 买“看住 Agent 的工具”，欧盟法院顾问给 RAG 划了一条线

- **CrowdStrike 的两笔收购（11 月 3–4 日）：** 宣布收购 Fiddler AI（AI 模型可观测与评估），TechCrunch 援引《华尔街日报》称另计划收购自动化 AI 安全测试公司 Dreadnode，报道价格分别约 4 亿美元与 9500 万美元——**这两个数字是报道口径，不是 Fiddler 公告披露的金额；** CrowdStrike 计划把 Fiddler 的能力作为 Falcon Observe 出售，覆盖部署前评估、Agent 链路追踪、行为监控与审计证据，目标为 2027 财年第四季度上线与交割（公司计划，非既成事实）。对买家而言，关键问题不是“买了谁”，而是“合并后的平台能否导出完整链路、能否在 Agent 越界时拦住它、以及合同里有没有写明交付日期”。
- **人事信号：** Claude Code 与 Cowork 的产品负责人 Cat Wu 于 11 月 3 日宣布离职（上周五为最后工作日，原因与去向未披露）。这不等于产品出问题，但对已把 Claude Code 标准化进工作流的团队，值得确认后续的路线图负责人与支持联系人，并保留可移植的评估与工作流，不把全部流程押在单一产品上。
- **欧盟法院总检察长意见（C-250/25，Like Company v Google Ireland，11 月 3 日）：** 这是**正式法律意见，不是终审判决**，法院尚未决定是否采纳。核心区分值得所有做新闻搜索、研究助手与 RAG 的人记下：**“检索到”不等于“可以再现”**——绕过有效访问限制，或生成答案的可识别表达完全替代原文，可能触及出版者权利；而单纯的事实本身仍与受保护表达有别；关于训练的文本与数据挖掘例外讨论是附条件的，不是 blanket 授权。**实操含义： lawful 的抓取解决不了下游复用问题，引用不等于许可，输出替代性要单独审计。**

### 6. 现实水位与供给侧：Uber 的 4 单、Oracle 的弃单、以及一张没兑现的支票

- **Uber 财报电话会（11 月 4 日）：** 万圣节当周，Uber 与 Uber Eats 合计约 3.2 亿单中，第三方 AI Agent 约下了 500 单外卖、打车仅 4 单；CEO 称“非常早期、非常有限”，同时指出应用内下单中位时间仅约 50 秒（外卖复购约 90 秒）——**Agent 要替代的不是“找不到入口”，而是“已经很快”的流程。** 口径提醒：TechCrunch 把 4 单写在万圣节当周，另一些整理写为“本季度”，电话会原文未明确划定打车数的统计窗口；因此本报告不把 4 单直接除以季度总量算比率，只陈述“4 单”这个披露本身与“约 500 单外卖 / 约 3.2 亿单当周总量”这两个有明确窗口的数字。**这是第一次有平台公开量化第三方 Agent 的真实订单量——它给所有“Agent 将绕过平台”的叙事钉了一个可检验的起点。**
- **供给侧的三条消息（均为单源日报转述，须标注）：** 据《金融时报》报道，Oracle 在白宫施压下放弃了向腾讯出租至多 10 万片先进芯片、为期 5 年、约 70 亿美元的租约，Oracle 未公开评论；据 Bloomberg 报道，阿里、腾讯、字节等订购了约 600 万片 Nvidia RTX Pro 5500（约 700 亿美元），预计 4 个月内仅交付约 1%——工作站卡被 8 卡一组装进服务器跑模型，已成为绕过供给约束的现实路径；据 Gurman 报道，Apple 把部分工程师的日 AI 支出上限从 300 美元降至 200 美元、计划进一步降至 100 美元（Apple 未确认）——**推理正在从资本开支变成按人头摊的运营成本，预算会最先体现在工程师每天能用什么模型上。**
- **研究侧的一盆冷水：** 一项预注册测试（每领域 100 个 LLM 提案对 100 个随机提案，跨三档验证强度）发现，分数随验证强度上升，但 LLM 相对随机对照的优势并不随之扩大，在最严一档反而缩小；真正起作用的是扩大提案池（混合提案池带来 +1.52 个 holdout-value 单位，p=0.0002）。另一项田野研究里，12 名研究者 100 分钟冲刺中的 33 次 AI 交互，仅 1 次被直接接受、27 次无记录处置。**结论不是“研究 Agent 没用”，而是“生成能力已经跑赢了验证能力”——瓶颈在验证，不在生成。**

## 三、给 Patrick 的实用启示 / 可以试用的点

1. **今天就能试的三件事（按成本从低到高）：** 其一，腾讯 Hy4 的免费窗口只到 11 月 15 日——在 WorkBuddy/CodeBuddy 里拿一个真实办公任务（截图改 UI、长文档整理、多步骤表格处理）实测它的视觉 + 电脑操作，而不是只看榜单；其二，Ripple 在 OpenRouter 经 GMICloud 的 $0.20/$0.60 很便宜，但下单前先确认端点上下文（当前仅 16,384 token），长上下文任务不要按 1M 去规划；其三，Kimi K3.1 Pro 的 API（$2/$10）仍是试它最现实的路线，权重留给有 8 卡级硬件的团队评估。
2. **如果你在用 Conductor Cloud，11 月 20 日前导出数据。** 只读从 11 月 13 日开始，关停后公司开始删除云数据；同时把并行 Agent 的工作流（工作区划分、提示词、评审流程）记成与工具无关的文档，下一个编排工具来了能直接迁移。
3. **给 Agent 项目立一条“Uber 式”验收线：** 不要只汇报“演示成功了几次”，而是汇报“真实任务里完整走完的比例”——Uber 的 4 单提醒我们，支付、地址确认、对方追问这些“无聊的中间环节”，恰恰是 Agent 最容易断、平台最难让渡的地方。你的项目如果也在这些环节上卡住，先修流程与权限，再谈模型升级。

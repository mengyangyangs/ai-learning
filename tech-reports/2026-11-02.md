# 每日 AI 技术报告 · 2026-11-02

**日期：** 2026 年 11 月 2 日（星期一）
**今日技术主题一句话概括：** 微调与对齐不是“再训一遍模型”，而是三道工序各管一件事——SFT 教模型“按格式答题”，偏好对齐教它“哪个答案更合意”，可验证奖励的强化学习教它“把题做对”；而三道工序共用的陷阱只有一个名字：奖励信号被钻了空子。

> 说明：本报告基于 2026 年 11 月 2 日通过浏览器阅读的公开资料写成，包括 DPO 论文与 DeepSeekMath 论文原文的关键章节、InstructGPT 与 LoRA 论文要点、后训练综述、GRPO 与 DPO 的实务深挖、长度偏差专题。文中凡是单篇论文、单家厂商指南或单次测量的数字，均已标注来源与条件，不是通用结论；凡是“某来源的建议”，均已说明适用边界。

## 一、通俗解释：基座模型是个“会续写的实习生”，后训练是三轮入职培训

想象你招了一个读过整个互联网的实习生：

- **预训练结束时，他只会一件事：续写。** 你给他一句“请写一份请假条”，他可能续写成另一份请假条的范文、也可能续写成网友对请假条的评论——因为他学的是“互联网上这句话后面通常跟什么”，不是“你想要什么”。
- **第一轮培训（SFT）：教格式。** 给他几千到几十万份“问题 → 理想答案”的示范，让他学会：被问问题时要回答问题、按要求的格式回答、保持助手的口吻。这一步不教新知识，教的是“把已有的能力摆成可用的样子”。
- **第二轮培训（偏好对齐）：教品味。** 同一个问题给他两个答案，让他知道人类更喜欢哪一个：更准确、更安全、更简洁、更有帮助的那一个。这一步回答的是“几个 plausible 的答案里，选哪个”。
- **第三轮培训（可验证奖励的 RL）：教做对。** 对数学、代码这类“对错可判定”的任务，让他自己多做几遍，做对的思路被强化、做错的思路被压低。这一步回答的是“能力本身能不能再往上提”。

先把两个词分开，否则后面全会混：**post-training（后训练）**是厂商把基座模型做成通用助手的全套工序（百万级样本、多阶段）；**fine-tuning（微调）**是你拿到一个已经做好的助手后，为某个具体任务、某个领域再调一下（通常 1 万–100 万样本）。两者用的技术高度重合，规模与目标不同。今天讲的 SFT、RLHF、DPO、GRPO，是贯穿两者的同一套工具箱。

## 二、第一道工序：SFT 与 LoRA——先学会“按示范答题”，再谈“省着训”

### 1. SFT 在做什么

SFT 的目标函数就是预训练的老朋友：下一 token 预测（交叉熵），只是数据换成了“指令 → 回答”对。关键点不在于公式，而在于数据：

- **质量大于数量。** 后训练综述引用的 LIMA 实验（Meta，2023）表明，1000 条精心挑选的指令回答对，效果可接近 GPT-4 级别的表现——这句话的适用范围是“该研究的评测与模型”，不能推广为“1000 条数据就够了”；但它指对了方向：系统性错误（例如学术回答里持续编造引用）会在 SFT 里被整个模型学过去。
- **数据质量有三根支柱：** 准确（每条回答事实正确、格式恰当）、多样（覆盖指令类型、领域与难度，否则冷门类型会在训练中被“灾难性遗忘”）、复杂（ deliberately 加入多轮、多步骤、需要维持上下文的任务，否则模型只会做单步简单题）。
- **一个可参考的配比（SmolLM2 数据集的二手分析，非放之四海的标准）：** 数学 39.4%、代码 38.9%、对话 17.6%、指令遵循 4.1%。数学与代码占比高不是偶然——它们的对错最容易判定，训练信号最干净；而对话与主观判断的信号最 noisy，反而要用更小但更高质量的数据。

### 2. LoRA：为什么“只训一小部分”也能work

全微调要更新全部参数：70B 模型在 FP16 下需要多卡、训数天。LoRA（Hu 等，微软，2021）的洞见是：**微调时权重真正需要的改动，藏在一个低维空间里。**

- **做法：** 冻结原始权重 W0，不直接改它，而是给每一层注入两个小矩阵 A 与 B，实际权重为 W = W0 + BA，其中秩 r 远小于矩阵维度。A 用 Kaiming 初始化、B 置零，保证训练开始时 ΔW = 0（模型行为与原来完全一致，再慢慢学）。
- **效果（论文原话的适用范围）：** 以 GPT-3 175B 为例，相比 Adam 全微调，可训参数减少 10000 倍、显存需求降为约 1/3，在 RoBERTa、DeBERTa、GPT-2、GPT-3 上与全微调相当或更好；且训练结束后可把 BA 合并回 W0，**推理时零额外延迟**（这是它胜过 adapter 类方法的结构优势）。r 越大越接近全微调的表达能力，但收益递减——r 不是越大越好。
- **QLoRA（Dettmers 等，2023）再往前一步：** 把基座模型先量化到 4-bit，再挂 LoRA 适配器。后训练综述称，70B 模型可因此在单张 24GB 消费级显卡上微调，质量约为全微调的 80–90%（该综述的概括口径，实际取决于任务与数据）。对个人与小团队，这就是“能不能动手”的分水岭。
- **选型口诀：** 要最高质量且算力充足 → 全微调；要性价比与快速迭代 → LoRA；算力受限、想先跑通数据实验 → QLoRA。三种方法的区别不在“聪明程度”，而在“你愿意为多少参数付显存账单”。

## 三、第二道工序：RLHF 与 PPO——先请人“打分”，再让模型“追分”，但要拴一根绳子

这是 InstructGPT（Ouyang 等，OpenAI，2022）确立的经典三段式，也是理解 DPO 与 GRPO 的参照系：

### 1. 三段

1. **SFT：** 标注员写理想回答，模型模仿。
2. **奖励模型（Reward Model）：** 对同一 prompt 采样两个回答，请人选更好的一个；奖励模型学的就是“给 chosen 打分高于 rejected”。偏好服从 Bradley-Terry 模型：人选 A 而非 B 的概率 = σ(r(A) − r(B))，即分数差越大、被选中的概率越接近 1。奖励模型通常以 SFT 模型为底、最后一层加一个输出标量的线性头。
3. **PPO 优化：** 把 SFT 模型当作策略（policy），用 PPO 让它去最大化奖励模型的分数，同时用 KL 散度惩罚把它拴在参考模型（通常就是 SFT 模型自己）附近。

### 2. KL 惩罚为什么是“牵引绳”，而不是装饰

奖励模型只是**代理（proxy）**：它在有限数据上学到的人类偏好近似，不是人类偏好本身。没有约束地追分，模型会跑到奖励模型没见过的区域，产出“分数极高、实际极差”的文本——这就是**奖励 hacking（reward hacking）**，本质是 Goodhart 定律：指标一旦成为目标，就不再是好指标。

- **β 就是绳子的长度：** 目标函数 max E[r] − β·KL(πθ‖πref) 中，β 大 = 绳子短（安全、收益小），β 小 = 绳子长（代理分数高、风险大）。PPO 还用“裁剪”限制单步走多远（新旧策略的概率比被 clip 在 1±ε 内），防止一次更新把策略拽出分布。
- **InstructGPT 的实测（论文口径，仅限其 prompt 分布与标注员）：** 175B InstructGPT 被偏好胜过 175B GPT-3 的比例约 85±3%，胜过精心 few-shot 的 GPT-3 约 71±4%；**1.3B 的 InstructGPT 也胜过 175B 的 GPT-3**——配方胜过参数量，是这篇论文最出名的一句话。闭域摘要的编造率从 41% 降至 21%，TruthfulQA 上“真实且有信息”的回答约翻倍。但代价与局限同样写在论文里：不加“请尊重”指令时毒性优势消失；偏见基准无改善；仍会接受错误前提、过度对冲；为防止能力退化而混入预训练目标（PPO-ptx）后，仍在 DROP、SQuADv2、翻译上落后于 GPT-3——而单纯把 KL 系数加大到默认值的 100 倍（1.3B 消融中 β=2.0）也修不好这几项回退。**KL 不是万能药，数据混合才是。**

### 3. PPO 的工程代价：四张牌桌

经典 PPO-RLHF 训练时要同时 hold 住：策略模型、参考模型、奖励模型、价值模型（critic，估计每个状态的期望回报以降低方差）。以 7B 模型、混合精度 AdamW（每参数约 16 字节：bf16 权重与梯度各 2、fp32 主权重 4、两个 fp32 动量 8）估算，单策略就约 112GB，须用 ZeRO/FSDP 分片；critic 还要再加一个同量级的模型与优化器状态。更麻烦的是理论上的脆弱：语言任务的奖励通常只在**最后一个 token**才给，critic 却要为每个中间 token 估计价值——长推理链上这个估计的方差极大，训练容易崩。这正是 GRPO 要动刀的地方。

## 四、DPO：把“打分 + 追分”两步并成一步——论文到底证明了什么

DPO（Rafailov 等，斯坦福，2023）的标题已经剧透了结论：《你的语言模型 secretly 就是一个奖励模型》。

### 1. 核心推导（三步，缺一不可）

1. **KL 约束奖励最大化问题有闭式最优解：** 最优策略 πr 与奖励 r 的关系是 πr(y|x) ∝ πref(y|x)·exp(r(x,y)/β)。也就是说，给定一个奖励，最优策略长什么样，是可以直接写出来的，不需要 RL 去“搜”。
2. **反解奖励：** r(x,y) = β·log(πr(y|x)/πref(y|x)) + β·log Z(x)，其中 Z(x) 是只与 prompt 有关的配分函数。
3. **代入 Bradley-Terry 模型，Z(x) 被抵消了：** 偏好概率只依赖奖励**差**，而奖励差里两项的 β·log Z(x) 相互抵消。于是人类偏好概率可以直接写成策略与参考策略的对数比之差，得到 DPO 损失：

$$L_{DPO} = -\mathbb{E}[\log \sigma(\beta \cdot \log \frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \cdot \log \frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)})]$$

其中 yw 是被选中的回答、yl 是被拒绝的回答。这是一个普通的二分类交叉熵损失：**不需要显式奖励模型、不需要训练时采样、不需要 RL 循环**。论文的理论保证是：在 Bradley-Terry（可推广至 Plackett-Luce 排序）假设下，DPO 隐式优化的目标与 RLHF 相同，且换元不损失奖励表达能力——因为相差仅为 x 的函数的奖励属于同一等价类，诱导同一偏好分布与同一最优策略。

### 2. 梯度在干什么：不是“抬高好的”，而是“按错的程度加权”

DPO 的梯度 = −β·E[σ(隐式奖励差为负)·(∇logπ(yw) − ∇logπ(yl))]。权重 σ(·) 的意思是：**模型越是把顺序排错，这个样本的梯度越大**；模型已经排对的样本，梯度自然变小。论文特别指出，去掉这个动态权重、用朴素的概率比目标，会导致模型退化——这就是“简单”背后的全部机关。

### 3. 实务工作流：DPO 失败，十次有九次不在损失函数上

综合 2026 年 10 月的 DPO 实务深挖，正确的操作顺序是：

1. **先有扎实的 SFT 检查点。** DPO 假设模型已经会“按格式答题”，SFT 检查点同时是起始策略与冻结的参考模型。对 base 模型直接跑 DPO，学到的主要是格式，不是偏好。
2. **偏好对要 on-policy。** 从自家 SFT 模型采样多个答案、打分、取最好与最差成对；丢弃分数接近的平局对（那多半是标签噪声）。用更强模型生成的答案来训自家小模型，梯度多花在模型永远不会生成的文本区域，生成时的改善很小。
3. **控长度捷径。** 检查 chosen 与 rejected 的长度比；若 chosen 系统性地更长，模型会先学会“说得更长”，而不是“说得更好”。处理办法：平衡长度，或改用长度归一化的损失（如 SimPO 风格的 sigmoid_norm）。
4. **防截断、防参考错配。** max_length 截掉 chosen 的关键结尾，等于教模型“结尾不重要”；参考模型不是起始检查点，则从第一步起所有隐式奖励都失去意义。
5. **读指标，而不是只看 loss 下降：** 初始 loss 必须接近 0.693（−log 0.5），偏离即掩码、模板或参考出错；训练几十步内 rewards/accuracies 冲到 1.0 附近，说明配对过于简单（常由长度或格式区分）；**chosen 的 logp 稳步下跌本身不致命**——DPO 的损失只看边际， cheapest 的满足方式常常是同时压低两者、rejected 压得更快；但跌幅过大意味着概率质量流向了两个答案之外的怪文本，生成质量会跟着垮；边际无限增长而留出集准确率不动 = 过拟合，减轮数、加数据或提高 β。
6. **轮数与变体：** 通常 1–3 遍；变体按症状选：ipo 治近确定性偏好的过拟合（把边际回归到目标值而非越推越高），robust + label_smoothing 治噪声标签，加 sft 项保住 chosen 的似然。一次只改一个变量，在同一留出集上比。
7. **评测三件套，缺一不可：** 留出偏好对的准确率（模型没训过的数据上的隐式奖励比较）；新 prompt 上与 SFT 模型的胜率（同一打分标准、换位消位置偏见、**同时报告长度**）；原任务回归套件（偏好调优会悄悄吃掉配对没覆盖的能力）。三项都过才发货；然后可以迭代：用新模型采样 → 打分 → 成对 → 再训一轮。

### 4. DPO 的边界：离线，是优点也是天花板

DPO 训练时不采样，数据是训练前固定好的。一旦策略在训练中漂移，旧配对就逐渐“过时”——这叫分布漂移，须靠迭代 DPO 缓解。主观对齐（helpfulness、harmlessness）上 DPO 是默认选择；但对最复杂的安全关键行为，后训练综述的共识是：专用的奖励模型能捕捉的细微差别仍有价值，前沿实验室多为“DPO 先做一遍对齐、RLHF 再针对安全关键领域补一遍”的混合路线。2025 年 7 月普林斯顿与伊利诺伊的一项研究还提醒：DPO 的隐式奖励基于 token 对数比之和，其学习动态与显式奖励模型不同，可能过度拟合偏好数据里的表层 token 模式——把 DPO 当作“免费午餐”之前，先留出集验证它学到的是品味还是花招。

## 五、GRPO：把“请人打分”换成“让模型自己比”——以及它为什么最适合教推理

### 1. 从 PPO 到 GRPO，只改了一个零件：基线

PPO 的优势（advantage）= 实际回报 − critic 预测的期望回报。GRPO（DeepSeekMath，Shao 等，2024，arXiv 2402.03300）把 critic 整个拿掉，改成：**对同一问题采样一组 G 个回答，用这组回答自己的奖励均值与标准差当基线。**

$$\hat{A}_i = \frac{r_i - \mathrm{mean}(r_1,\dots,r_G)}{\mathrm{std}(r_1,\dots,r_G)}$$

同一输出的所有 token 共享这个优势；损失仍是 PPO 式的裁剪替代目标（新旧策略概率比 clip 在 1±ε），KL 项则直接加在损失里（用恒非负的 k3 估计量 ref/pi − log(ref/pi) − 1），而不是像 PPO 那样折进每 token 的奖励——这样优势计算就不与正则信号纠缠。

为什么这招对推理特别有效？因为推理任务的奖励天然是“组内可比”的：同一道数学题，8 个解法里对的就是对的、错的就是错的，不需要一个学出来的价值网络来猜“这个中间步骤值多少分”。DeepSeekMath 的原始实验也提醒一点常被误读的事实：**原始 GRPO 用的仍是奖励模型**（在指令微调数据上训的），不是后来 RLVR 路线里的纯规则验证器；规则验证器是 R1 之后才成为主流的“奖励函数”形态。两者共享 GRPO 的组内比较机制，但奖励来源不同，结论不能直接互换。

### 2. DeepSeekMath 的原始数字（论文口径）

- 基座：DeepSeek-Coder-Base-v1.5 7B 继续用 120B 数学相关 token（Common Crawl 经 fastText 分类器迭代挖掘）预训练，得到 DeepSeekMath-Base 7B；MATH 36.2%、GSM8K 64.2%，已可比肩 Minerva 540B——作者的论点是：参数量不是数学能力的唯一决定因素，数据质量与筛选 pipeline 同样关键。
- 指令微调后 DeepSeekMath-Instruct 7B：MATH 46.8%、GSM8K 82.9%。
- GRPO 后 DeepSeekMath-RL 7B：MATH **46.8% → 51.7%**、GSM8K **82.9% → 88.2%**，且在未参与 RL 的域外基准上亦有提升。训练设置：RL 数据为 GSM8K/MATH 的 CoT 格式 SFT 数据约 14.4 万题，策略学习率 1e-6、KL 系数 0.04、**每题采样 64 个输出**、最大长度 1024、批大小 1024、每轮探索后只更新一次。
- **过程监督（Process Supervision）胜过结果监督（Outcome Supervision）：** 结果监督只在输出末尾给一个奖励；过程监督在每个推理步末给奖励、组内归一化、token 优势为后续各步归一化奖励之和——对多步推理，细粒度信号更有效。
- **迭代 RL：** 奖励模型会跟不上策略的进步，因此用新采样数据持续训奖励模型（replay 保留 10% 历史数据），并把参考模型重置为当前策略；实验中两轮迭代，第一轮提升最大。
- **RL 到底提升了什么？** 论文的 Pass@K/Maj@K 对照给出一个反直觉的答案：RL 提升 Maj@K（多数投票准确率），**不提升 Pass@K（K 次采样中至少对一次的概率）**。也就是说，RL 主要让输出分布更稳健——把正确答案从 TopK 里顶上来、让正确思路更常出现，而不是凭空赋予模型原本没有的能力。这个结论对“RL 能不能教出新能力”的争论，至今仍是最诚实的刻度之一。

### 3. 统一范式：SFT、RFT、DPO、PPO、GRPO 其实是同一张表

DeepSeekMath 第 5 章把所有方法写成同一个梯度形式：梯度 = E[数据来源 × 梯度系数 × ∇logπ]，三要素决定一切：

| 方法 | 数据来源 | 奖励函数 | 关键区别 |
|---|---|---|---|
| SFT | SFT 数据 | 无 | 梯度系数恒为 1，照单全收 |
| RFT（拒绝采样微调） | SFT 模型采样，经规则过滤 | 规则（答案对错） | 只强化正确答案，不惩罚错误答案 |
| DPO | SFT 模型采样，成对 | 规则（偏好对） | 离线；按偏好边际奖惩 |
| Online RFT | 实时策略采样 | 规则 | 在线；后期显著胜过离线 RFT |
| PPO | 实时策略采样 | 模型（奖励模型） | 需 critic，方差大 |
| GRPO | 实时策略采样，一组 G 个 | 模型或规则 | 组内比较，按奖励大小差异化奖惩 |

实验结论排成一句话：**在线胜过离线（后期差距拉大），差异化奖惩胜过只奖不罚，过程监督胜过结果监督，迭代胜过一轮。** 这张表也是选型的地图：你的瓶颈在数据来源、奖励函数还是梯度系数，先定位再换方法，而不是追新方法的名头。

### 4. GRPO 的系统账：省下的 critic，又以生成成本还了回去

去掉 critic 省下一个模型量级的显存与一次前后向，但每步要为 B 个 prompt 各生成 G 个长回答。实务深挖给的算术：64 个 prompt × G=8 × 平均 1000 token = **每步 51.2 万生成 token**，且生成是自回归、受显存带宽限制（读权重与 KV 缓存），不是算力限制；模型越学越会“想得更长”，步耗时还会随训练增长。因此 GRPO 训练循环里必须塞一个高吞吐推理引擎（如 vLLM）：前缀缓存让同一 prompt 的 G 个样本共享 prompt 的 KV 缓存，连续批处理让长短不一的样本不互相空等。布局上，同卡部署（colocate）省硬件但两阶段轮流空闲，分卡部署可重叠生成与训练、但每步要传全量权重且略微 off-policy——小模型与单节点选前者，大模型与长回答选后者。还要盯一个容易被忽略的量：采样引擎与训练器对同一 token 算出的 logp 可能因 kernel 与精度不同而有偏差，TRL 会记录 `sampling_logp_difference`，布局一变先看它。

### 5. Dr. GRPO 与 DAPO：原始 GRPO 的两个偏差，是怎么被修掉的

原始 GRPO 有两个被 2025 年论文点名的偏差，都与“长度”有关：

- **长度偏差：** 原始损失先对每个回答的 token 取均值、再对组取均值，于是 100 token 答案里的每个 token 权重是 1000 token 答案里 token 的 10 倍；结合“除以组标准差”，近全对/近全错的 prompt 会被过度加权。结果是模型慢慢学会“写长而错的答案”。**Dr. GRPO 的修复：** 除以固定长度、不除标准差。
- **熵坍塌与零梯度组：** 对称裁剪会过早锁死探索；全组奖励相同（全对或全错）时梯度为零，整组生成白算。**DAPO 的修复（四件套）：** clip-higher（上界放宽，让低概率 token 有机会涨起来，减缓熵坍塌）、动态采样（丢弃全等奖励组，保证每批都有梯度）、token 级损失（全批 token 等权）、超长奖励塑形（被截断的回答渐进扣分，而非直接判负）。许多可验证奖励的配方还会把 KL 系数设为 0，彻底去掉参考模型。
- **失败症状速查表（实务深挖原表改写）：** 奖励平坦、学不到 → `frac_reward_zero_std` 接近 1，prompt 过易或过难，过滤或提高 G；长度涨、准确率不涨 → 长度偏差或截断判负，换 token 级/固定长度聚合、掩掉截断样本；奖励涨、评测跌 → 奖励被钻空子，加固验证器、每几百步人工抽查样本（只看曲线不够）；输出越来越重复 → 熵坍塌，放宽上界裁剪或降学习率；换布局后训练不稳定 → 采样与训练 logp 不一致，对齐精度或用重要性比率修正。
- **格式奖励的经典死法：** 格式分给得太大，模型会学会“用整齐的 `<answer>` 标签包着错误答案”。实务配方里格式奖励被刻意设得很小（如 0.2 对 1.0 的正确性分），且被截断的样本直接从损失中掩掉——**先写验证器、并用已知好坏答案测验证器，再开训；GRPO 的失败，十次有九次从奖励函数开始。**

## 六、长度偏差：为什么对齐后的模型都变啰嗦了

这不是某个方法的 bug，而是四层叠加：

1. **数据层：** 偏好数据本身轻微偏长——只选更长者与人类标签的一致率在 WebGPT 55.7%、Stack 59.6%、RLCD 63.1%（Singhal 等，2023），高于无偏的 50%。
2. **奖励模型层：** 奖励模型会把这点倾向学成捷径，且比数据本身更偏长；一项实验中，仅用长度启发式奖励的 PPO 就取得与标准 PPO 相近的胜率（WebGPT 56% 对 58%、RLCD 64% 对 63%）。
3. **优化器层：** DPO 的隐式奖励是 token 对数比之和，随长度增长，Park 等（2024）称未正则的 DPO 在 HH 与 TL;DR 上使平均回答长度翻倍；GRPO 原始的逐序列均值同样偏长（见第五节第 5 点）。
4. **评测层：** LLM 评委本身也偏爱更长的回答，于是“变长”在评测里被记成“变好”。
**结论是：只修一层没用。** 数据层平衡长度、损失层归一化、评测层同时报告长度与胜率，三处同时动手，啰嗦才会真正下去。推理模型的“变长”要分开看：那里的长度增长若伴随准确率提升，是思考变深；若准确率不动，才是长度偏差。

## 七、选型总表：手里有什么信号，就选什么方法

| 你手里有的信号 | 默认方法 | 代价与注意 |
|---|---|---|
| 输入输出示例 | SFT（LoRA/QLoRA） | 最便宜；数据质量决定一切 |
| chosen / rejected 回答对 | DPO | 稳定、离线；须迭代防分布漂移 |
| 可编程验证器（数学答案、代码测试、格式/JSON） | GRPO / RLVR | 在线生成是主成本；验证器质量决定成败 |
| 主观安全对齐，DPO 效果不足 | 完整 RLHF（PPO） | 最贵、最不稳定；留给安全关键领域 |
| 只有点赞/点踩的单信号 | KTO | 信号最弱，期望值相应放低 |
| 什么都没有，只有 prompt | 先提示词 + RAG，攒数据再说 | 没有信号的方法都是空转 |

一个容易踩的坑要单独写出来：**不要用 DPO 的思路去训 GRPO 的任务，也不要反过来。** DPO 只能从“已有的两个答案里选更好的”，它学不到“从未出现过的正确解法”；GRPO 只能在“对错可判定”的任务上成立，把主观品味硬写成规则奖励，模型会迅速学会钻规则的空子——例如把格式分刷满、把答案写长、把测试用例背下来。方法没有高低，只有信号是否匹配。

## 八、给 Patrick 的实用启示

1. **如果你想亲手跑一次（最小可行路线）：** 从 QLoRA SFT 起手——单卡、开源小模型、几千条自己领域的高质量问答对，先拿到一个“格式正确、口吻稳定”的模型；再用它自己采样、按你的评分标准（或验证器）打分、做几千对偏好数据，跑一轮 DPO；**只有当你的任务有可靠验证器（单元测试、答案比对、JSON Schema）时，才上 GRPO**，且第一步是写验证器并用已知好坏答案测它，而不是先调训练参数。工具上，Unsloth 适合快速跑通 SFT，TRL 适合 DPO/GRPO 与自定义奖励函数；TRL 的默认值随版本变化（包括默认损失类型与 KL 系数），关键参数要显式写出并锁定版本。
2. **读训练曲线的方法（照着抄）：** DPO 先看初始 loss 是否约 0.693，再看 chosen logp 与边际的组合；GRPO 先看 `frac_reward_zero_std`（多少 prompt 的整组奖励相同）、平均长度与截断率，再看奖励曲线。**奖励涨而留出评测跌，是停训检查验证器的信号，不是加大训练量的信号。**
3. **工作中判断供应商说法的标尺：** 听到“我们用了 RLHF/DPO/GRPO”，追问三件事——训练信号是什么（人工偏好对？规则验证器？学出来的奖励模型？）、数据是否 on-policy（是不是模型自己生成的）、评测是否同时报告了长度与留出集表现。答不上这三件，方法名只是营销词。
4. **把今天的技术与昨天的资讯连起来看：** Mistral Large 4 开放权重后三周 RL 带来的 Terminal-Bench 提升、DeepSeek Super-agent“用 token 换速度”的取舍、Anthropic 新政里“断连保持安全状态”的要求，都是同一条主线——**后训练的成本与规则，正在从论文里的超参数，变成产品账单与合规条款。** 读模型发布时，多问一句“它的后训练信号是什么”，比多记一个基准分更有用。
